# Large-Scale Observability for Ride-Hailing Fleet — Multi-Turn Task (Hardened v9, NOT API log analysis)

This is a multi-turn terminal-bench task with 2 steps, now significantly hardened and explicitly NOT a generic API access log analyzer (no JSON log file parsing, no request-counts/error-rates/latency-percentiles/unique-users aggregation). You are building a ride-hailing fleet observability SDK in Go for a high-throughput dispatch platform handling 10k+ req/sec, tracking riderID -> driverID matching, pickup/dropoff lat/lng geohash, trip lifecycle requested/matched/started/completed, driver heartbeat presence, ETA calculation, surge pricing, fleet dispatch optimization, fare aggregation.

## Overall Goal
Implement package `observability` in module `ride-observability` that provides:
- Distributed tracing with `TraceContext` (TripID 32 hex, SegmentID 16 hex) propagation via custom single-header `x-ride-trace` = tid:sid:pid:1/0 (4 colon parts even when pid empty as tid:sid::1), with strict Flags 1/0, ParentID chain consistency across root->child->grandchild, nil ctx handling, defensive copies, duplicate-key last-wins, distinct counting 128 limit, all-zero IDs invalid for propagation, Flags normalized in ContextWithTrace, sampled false still stored and marshal :0, always sampled true even if parent sampled false
- Ride metrics (Counter for ride_requests_total, Gauge for active_rides, Histogram for ride_duration_seconds/ETA) with thread-safety, defensive copies for WithLabels map and WithBuckets slice (mutating original after creation must not affect), label value truncate 256 before cardinality key and reuse after truncation (collision reuse), label key validation hyphen and digit-start and space invalid, sorted keys order irrelevant, Gauge Set/Add ignore NaN/Inf, Counter Add >=0 ignore negative/NaN/Inf, Histogram default buckets 11 cumulative inclusive sorted ascending with dedup and NaN/Inf filtering, deep copy Collect, provider isolation, type conflict first wins
- Structured JSON logging correlated with tracing for trip events (ride requested, driver matched, trip started/completed, surge triggered), atomic per-line writes, shared mutex across With chain for 100 concurrent goroutines producing 100 valid JSON lines no interleaving, immutable With and backing array isolation, level filtering debug<info<warn<error> default info case-insensitive warning alias, WithOutput nil fallback stderr, service field cannot be overridden, field duplicate last-wins, timestamp RFC3339Nano UTC recent, concurrent exact lines
