## 2. Spec ⇄ Test Alignment

Task type: **implement-from-spec against an existing repo.** `instruction.md` points the agent at the existing repo; `engine.go`/`types.go` are agent-readable and act as source-as-spec for signatures and config semantics.

**Direction A — assertions not (fully) in spec:**
- `TestPredictiveFloorPeakOverWindow` requires sizing for the **peak** forecast load over the window. instruction L12 says only "based on the lookahead window"; types.go says "scan for predicted load" + "sampling interval when scanning the lookahead window" (implies sampling across the window) but **does not state the aggregation is the maximum**. A solution that scans and takes avg/last, or only the horizon point, could fail. → **Medium** (reasonable agent infers peak, but not explicit).
- `TestPredictiveFloorDisabled` requires **no upward floor when `step<=0`** (forecaster set, lookahead>0, step=0). instruction L12 says "off by default" and `DefaultConfig` leaves step=0, so off-when-step=0 is inferable; but the precise "step<=0 ⇒ no floor" edge isn't spelled out in spec or types.go. → **Medium** (borderline-fair; this is the dominant differentiator).
- All other assertions (immediate scale-up, transient-dip hold, gradual rate-limited scale-in, bounds, tolerance, FP-exact-integer, predictive scale-up off-by-default, predictive never-scales-down) are ✓ stated or ~ recoverable from agent-readable source.

**Direction B — requirements not tested:** none. Every instruction requirement has coverage (scale-up, transient-drop, gradual scale-in/min, bounds/tolerance, FP-exact-integer, predictive-up-only/off-by-default, predictive-no-scale-down).
