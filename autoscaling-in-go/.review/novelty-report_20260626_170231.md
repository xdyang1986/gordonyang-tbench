### 2. Algorithm Memorization Risk
- **Result:** MEDIUM
- **Goal vs building block:** The reactive HPA ratio rule (+ tolerance dead-band, stabilization window, rate-limited scale-in, bounds) is a recall-able algorithm, but it is now a **building block**, not the whole goal. The task additionally **requires** a predictive feature whose specified behavior is non-canonical: pre-scale **up only**, **off by default**, and **only on a clear sustained upward trend** (not on transient blips). Public predictive autoscalers are ML-based, so this heuristic is not a memorized unit.
- **Details:** A naive recall solution that pre-scales on *any* positive slope (the canonical default) produces the wrong behavior and **fails** the test suite — empirically verified: a 2-point/un-gated variant fails `test_predictive_ignores_transient_blips` (`on=[3,5,4,7,5,9]` vs reactive baseline `[3,3,3,3,3,3]`), so it fails the (all-or-nothing) task. This breaks the single-memorized-unit ("stock HPA") property that made the reactive-only version HIGH. **Modifier Gate / Component Composition applies:** memorizable pieces (HPA) + a non-memorizable, test-enforced required component (the sustained-trend gate) + a combination matching no single public source → downgrade to MEDIUM. The "Standard project template" exception does **not** fire: real predictive autoscalers are architected differently (ML), so the gated scale-up-only floor is not a memorized assembly template.
- **Ceiling note:** Because requirement 5 is intentionally specified at the *scenario* level (no formula revealed to the agent), recall resistance rests on the trend-gate alone (a "gate-only" posture). A careful model that reads "only on a clear sustained upward trend" can implement a passing gate — so this is solidly MEDIUM, not HIGH (the reactive core is still pure recall) and not LOW (the gate genuinely defeats one-pass canonical recall).

## Overall Novelty Risk

**Risk Level:** MEDIUM

**Summary:** The reactive core is the canonical, recall-able Kubernetes HPA, but the task now requires a bespoke, test-enforced predictive feature (sustained-trend gate, scale-up-only, off by default) that no public source implements (real predictive autoscalers are ML). A naive canonical-recall solution fails the transient-blip gate (empirically verified), so the task is not one-pass recallable. Because req 5 is specified at the scenario level (no formula leaked), recall resistance rests on the trend-gate, landing the task at a well-founded MEDIUM.

**Action:** MEDIUM → ship with awareness. The gated predictive feature achieved the intended reduction from the reactive-only HIGH; no redesign needed.
