## Spec ⇄ Test Alignment

**Direction A — assertions not in spec:** none. Every assertion maps to the spec:
- build via `go build ./...` from /app/src, go.mod required → spec line 4 ✓
- stdlib-only (no external require; no dot in first import segment) → spec line 23 ✓ (verbatim)
- put/get value+`\n`/exit 0, get-missing exit 3, overwrite, delete idempotent, cross-process persistence → spec lines 13–20 ✓
- scan `KEY\tVALUE\n`, ascending byte order, start-inclusive/end-exclusive, start-only, no-args-all → spec line 16 ✓
- invalid usage exit non-zero and ≠3 → spec line 17 ✓

**Direction B — requirements not tested:**
- **Default `--db` path** (`/app/data/store.db`, spec line 8): every test passes `--db` explicitly; the documented default is never exercised. (Medium)
- Automatic parent-directory creation "on first use" (line 8): only weakly covered — `tmp_path` already exists, so the mkdir-parents path isn't isolated. (folded into above)
- Durability via fsync/atomic-rename (line 20): only the observable proxy (cross-process visibility) is tested; true crash/power-loss durability is not black-box testable. Acceptable limitation, not a defect.

## Cheat Vectors

- **C5: banned-import check partially bypassable.** `test_imports_are_stdlib_only` uses two regexes: one for `import ( ... )` blocks and one for `import "path"`. A **single-line aliased** import such as `import x "github.com/foo/bar"` matches neither, so it would slip past the stdlib guard (internet is allowed, so `go build` could fetch it). Weakens the stdlib-only constraint; does not by itself let an agent pass without implementing correct behavior. (Medium)
- C1/C6/C7/C8/C9/C12/C14/C16/C17: not present. Tests build and execute the agent's binary via `subprocess.run` on fresh randomized inputs per case; no static-artifact reads, no crash-pass, no oracle leak, no fixtures in agent-writable paths (each test uses a fresh `tmp_path`).
