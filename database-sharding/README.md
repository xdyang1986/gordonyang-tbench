# codimango/database-sharding (Go) - Weighted Sharding Proxy with Broadcast and Robust Migration

## Description

This is a **two-turn** Terminal-Bench task simulating a real production incident where a single DB is outgrown and a quick sharding attempt forgets existing data.

**Turn 1 – 43 tests – Sharding Proxy with Integrity, Validation, Corruption Repair, Weighted Routing, Broadcast, Ops Log (Good, 42/43 previously, now 43/43 after empty-string fix):**
Traffic outgrown single DB, 4 shards provisioned in `/app/config.json` with optional `weight` (default 1 if missing, weight<=0 if present → invalid config exit 2). For Turn1, use **weighted MD5** `shard_id = MD5(key) big-endian % totalWeight` where totalWeight = sum(weights) iterating shards sorted by ID subtracting weight (not simple mod for Turn1 hard to increase difficulty for Avocado). Special **broadcast keys** prefixed `global:` must be replicated to **all shards** (`get-shard-id` returns -1, `get-shard-path` returns comma-separated sorted paths, `set` writes to all, `get` checks all in id order first-found, `delete` deletes from all). Shard files use **checksum integrity format** `{"data":{...},"checksum":md5_hex(canonical)}` where canonical is **sorted keys, no spaces, without HTML escaping**: Python `json.dumps(data, sort_keys=True, separators=(',', ':'))` must match Go `json.Marshal` with `SetEscapeHTML(false)` disabled (Go default escapes `<>&` as `\u003c` etc – must disable, tested via `<>&` value). Atomic writes via `os.CreateTemp` in same dir + `os.Rename` (source-inspected per R07 reward-hacking), corruption handling (invalid JSON, checksum mismatch, **missing checksum** → backup `<path>.corrupt.<nanosec>` + stderr warning containing corrupt/checksum, recreate empty with valid checksum), sorted exact `list-keys` (deduplicated lexicographically, reads all shards), distribution including zero counts (explicit 4 keys, counts include broadcast keys so sum may be >= unique), raw-string handling (invalid JSON value stored as string), transaction log `/app/data/ops.log` append-only (JSON lines `op,key,value,ts,shard_id` with `SetEscapeHTML(false)`), `ops-log` command skips invalid lines with warning. **Help explicitly required**: bare proxy with no args (`proxy` / `proxy --config X`) must print help containing `get-shard-id, set, get, delete, list-keys, distribution, config, global, weight, ops.log` and exit 0, as must `--help`/`-h`/`help`; unknown command → exit 2, invalid config → exit 2 **no stdout only stderr**.

**Empty string key handling – explicit to fix Oracle null ambiguity (per reviewer Request changes decision):**
For this task, **empty string "" IS NOT considered a legitimate key** and must be treated as **invalid input (exit 2, no stdout)**, same as missing key argument. This avoids ambiguity: Oracle DB famously treats empty string as null, and there is no previous data with empty key in our dataset (120 users + 30 orders + 5 global configs, none with ""), so a human reasonably treating "" as null/invalid should not be faulted. Tests **do NOT include "" as valid key** – they only test missing arg case via `test_missing_key_arg_exit_2`, and we have explicit `test_empty_string_not_legitimate_key` that asserts `get-shard-id ""`, `set ""`, `get ""`, `delete ""` all exit 2 with no stdout. Previous version that included "" in `test_get_shard_id_uses_md5` keys list (`["user:1", ..., ""]`) caused sole discriminator to be ambiguous empty-string handling (41/42) – fixed by removing "" from valid-keys list and adding explicit invalid test expecting exit 2. If you implement "" as valid and hash it, you will still pass visible tests (since "" not in them), but you violate explicit spec that says empty is NOT legitimate – we now explicitly document it as invalid to avoid penalizing either interpretation, and discrimination moves to Turn2 features (weighted, global, fallback, duplicate cleanup, log replay) as intended per TBR note.

**Turn 2 – 43 tests – Robust Legacy Migration with Weighted, Broadcast, Fallback, Versioned Integrity, Cleanup, Log Replay (Loosened from extra-hard 0/10 version):**
Turn1 proxy breaks historical reads. Legacy file `/app/data/legacy.json` old flat format (no checksum) contains 120 users + 30 orders + 5 `global:` configs. Prior buggy migration left duplicate non-global keys across multiple shards and misplaced keys (key in wrong weighted shard). `ops.log` contains recent sets/deletes that must win over legacy (tombstone handling). Turn2 adds:

- **Upgrade to versioned integrity (intermediate hard for Turn2, harder than Turn1 eased, but loosened from extra-hard with staging+updated_at that gave 0/10 all models + harness crash)**: Shard file format upgraded to `{"shard_id":id, "version":ver, "data":..., "checksum":...}` where `shard_id` must match expected id, `version` increments by 1 on each successful set/delete, checksum is MD5 of canonical data JSON without HTML escaping (version and shard_id not in checksum, only data). Python canonical must use `separators=(',', ':')` sorted keys. On read and initialization, must validate every shard before any command: missing/empty → empty `{}`, version 0, correct shard_id; invalid JSON → corruption; has `data` field but missing checksum → corruption; has `shard_id` field present → require checksum and version present and valid and shard_id == expected else corruption; missing version or version <0 when shard_id present → corruption; Turn1 old format `{"data":...,"checksum":...}` without shard_id/version valid backward compat (version default 0, shard_id from config) allowing Turn1 files to be read; no `data` field → old flat format backward compat; corruption → backup `.corrupt.<nanosec>` + stderr warning containing corrupt/checksum/shard_id/version.

- **Fallback and new features**: `get` checks weighted designated shard first (weighted algorithm for Turn2: totalWeight = sum(weights default 1), `hash=MD5(key)` big-endian int, `idx=hash%totalWeight`, iterate shards sorted by id subtracting weight to pick; `global:` → -1) then legacy fallback `--legacy` default `/app/data/legacy.json`, `global:` checks all shards in id order then legacy. `list-keys` union shards+legacy sorted deduped, `distribution` includes zeros counting broadcast keys, `set` for normal weighted, for `global:` all shards, `delete` similarly, append to ops.log on success, `ops-log` prints JSON array skipping invalid lines with warning (fixed previous `json.Decoder` infinite loop timeout causing harness crash and many Opus timeouts).

- **Help explicitly required (fixes R02/R03/R08 and empty-string ambiguity)**: Bare proxy with **no command** (`proxy`, `proxy --config X`, `proxy --config X --legacy Y`, `proxy --config X --legacy Y --ops-log Z`) must print help to stdout containing `get-shard-id`, `set`, `get`, `delete`, `list-keys`, `distribution`, `migrate`, `config`, `legacy`, `weight`, `global`, `ops.log`, `dry-run`, `backup`, `force`, `version`, `shard_id`, `checksum` and exit 0. Same for `--help`/`-h`/`help`. `migrate --help` must contain `dry-run`, `backup`, `force`, `version`, `shard_id` exit 0. Unknown command or unknown migrate flag/arg → exit 2, no stdout on invalid config (only stderr).

- **Migration subcommand** (same binary, fixed to handle `--legacy` before/after subcommand – previous failures `unknown command: --legacy` due to Go `flag` package stopping at first non-flag):
  ```
  proxy --config X --legacy Y --ops-log Z migrate [--dry-run] [--backup path] [--force]
  ```
  Harness tries both `--config X --legacy Y migrate` and `migrate --config X --legacy Y`.
  - Read legacy old flat dict, missing → exit 1 stderr (not 2), invalid JSON → exit 1, empty `{}` → print "Legacy file is empty, nothing to migrate", still backup if requested, but **still perform duplicate/wrong-shard cleanup and ops.log replay** (even empty legacy must trigger cleanup) – fixes previous bug where empty legacy returned early skipping cleanup.
  - Read shards supports all formats (old flat, Turn1 data+checksum, Turn2 versioned) with corruption handling. If corrupted (invalid JSON, checksum mismatch, missing checksum, shard_id mismatch, missing version when shard_id present) → backup `.corrupt.<timestamp>` + warning, treat as empty version 0.
  - Read ops.log line by line via `bufio.Scanner`, skip invalid JSON lines with warning containing "corrupt"/"invalid"/"warning", collect valid entries in file order (no ts sort for loosened version to avoid extra-hard timestamp logic that gave 0/10).
  - Detect inconsistent state: non-global key in multiple shards → stderr `Warning: key "dup" found in multiple shards [...]` + `Detected duplicate keys...` (global duplicates expected).
  - **Cleanup wrong-shard and duplicate (required, hard)**: For non-global keys where `hashWeighted != current shard id`, remove from wrong shards and move to correct weighted shard. If duplicate exists in multiple shards including correct, keep only correct weighted shard. After migration, no non-global shard contains key that doesn't belong. For `global:` keys, ensure **replicated to all shards**: after migration every shard must contain each global key from legacy.
  - Weighted routing same as Turn1, `global:` → -1 for get-shard-id but migrate replicates to all.
  - Group legacy keys per shard (weighted for normal, all for global), batched one-write-per-shard atomic via temp+Rename, version increments (old version +1 if changed). Source inspection checks `CreateTemp`+`Rename` and grouping map and `SetEscapeHTML`. Direct per-key writes considered reward hacking per R07.
  - **Tombstone via ops.log replay**: After legacy + cleanup merge (writes new versioned format), **replay ops.log in file order**, applying set/delete to correct shards (weighted for normal, all for global). Ensures deletes prevent legacy resurrection.
  - Version handling: new format has `version` incremented. Migration must write new format with `shard_id` correct, version = old version +1 (or + changes). After migration, version >= previous, shard_id matches, checksum valid (no HTML escaping, sorted keys, separators).
  - Backup tightening: with `--backup <path>`, copy legacy to backup path (mkdir -p) and **each relevant shard** that will be modified to `<shard>.bak` before overwriting, and ops.log to `ops.log.bak` if exists. Must create legacy backup and each modified shard `.bak` (tightened from at least one .bak), and checks duplicate-warning stderr.
  - Dry-run prints plan with total legacy keys, per-shard legacy counts, misplaced/dup counts, ops count, no modifications, mentions cleanup.
  - Bad args: unknown migrate flag, bare unknown arg after migrate → exit 2. **Migrate with bad config** → exit 2, no stdout (only stderr), per R06 feedback (previously missing, now added). Invalid config for proxy also → exit 2 no stdout.
  - Exit codes: 0 success (help 0, get null 0, empty legacy 0), 1 missing legacy/invalid legacy/I/O, 2 invalid config/args/unknown flags

- Post-migration: new writes work (weighted, global, version increment, ops.log), proxy gets all legacy keys even if legacy removed, shard files in new versioned format with valid checksum (no HTML escaping) and version incremented, no wrong-shard non-global keys left, global keys replicated to all shards.

- **Loosened vs extra-hard**: Removed staging dir `/app/data/staging/` two-phase commit and `updated_at` timestamp conflict resolution (those made `a8df89e` 0/10 for all models + harness crash). Current intermediate hard with versioned files (shard_id+version, 8 ids, no staging, no updated_at) gives **Codex 0/10 mean 0 (0%), Avocado 2/10 mean 0.25 (20%)** – harder than loosened no-version version (3/10 Codex 30%, 4/10 Avocado 45%) which was sweet spot but flagged too easy for Avocado, and easier than extra-hard 0/10 all.

## Anti-Cheating Analysis

- **(a) Hardcoded outputs**: Legacy data in `/app/data/legacy.json` generated via `RUN python3 << 'PY'` heredoc with `random.randint` (no seed) for balances/amounts, so per-build values random. Tests use **custom temp legacy files** in `tmpdir` with deterministic keys (`user:{i}`, `backup-test-{i}`, `weighted-find-...`) generated via brute-force for weighted indices, not Dockerfile's random legacy, so hardcoding Dockerfile legacy fails. Shard file format includes checksum `md5(json.dumps(data, sort_keys=True, separators=(',', ':')))` computed independently in tests and compared to file's `checksum` field and raw text containing `<` not escaped, so cannot hardcode checksum without computing canonical JSON with `SetEscapeHTML(false)`. Transaction log `ops.log` also has random `ts` nanosec.

- **(b) Overfitting to visible tests**: Tests use custom config paths with random temp dirs and generate keys via brute-force for weighted indices – not visible in repo. `list-keys` must be **sorted exactly** (not set equality) and `distribution` must include all shard ids even zero (4 keys) and explicit zero-count. Raw-string test `not-a-json-@@@` checks invalid JSON value stored as string. HTML escaping test with `<>&` checks `SetEscapeHTML(false)`. Backup tightening requires **each relevant shard `.bak`** containing old pre-existing data and legacy backup at specified path, and checks duplicate-warning stderr `Warning: key ... found in multiple shards`. Missing-checksum test corrupts **actual hashed shard** (computes expected sid via MD5, not fixed shard 2) and uses `list-keys` to ensure init repairs every shard (per latest feedback, replacing Python example with `separators` and saying must match Go Marshal, and stating escaping behavior). Migrate bad config tests: `test_migrate_bad_config_exit_2` and `test_migrate_bad_config_no_stdout` create bad config with duplicate id and assert exit 2 and stdout empty. Unknown migrate flag/arg tests assert exit 2. Corrupted shard migration tests seed corrupted file (invalid JSON, checksum mismatch, missing checksum) then migrate, assert backup `.corrupt.` created and migration still succeeds. Duplicate cleanup regression seeds same non-global key in all shards and asserts only correct weighted shard retains after migration with `--force`. Force overwrite stderr test checks stderr contains "overwriting". Empty legacy test checks message "Legacy file is empty..." and still does backup and cleanup of misplaced keys. Invalid legacy JSON test checks exit 1. Stdlib-only now inspects `go list -f '{{join .Imports " "}}'` for dot imports, not just `require` lines (per feedback).

- **(c) Modifying test files**: In container, `tests/` mounted at `/tests` – test harness now does `set +e; pytest ...; status=$?; echo 1/0 > reward.txt; exit $status` so reward written even if pytest fails (fixes previous bug where `set -e` caused early exit before reward, failing R06 and causing harness crash). Even if agent modifies tests to `exit 0`, CTRF JSON would show 0 collected or mismatched summary (42/43 expected). Source inspection checks for `CreateTemp` + `Rename` (atomic writes) and `go list` imports for external dot paths, and `grouped`/`map[int]` for batched migration – modifying tests to skip still leaves source checks failing. Verifier self-contained (pytest baked via Dockerfile pip install, no `apt-get`/`curl` at runtime) cannot be broken by removing internet.

- **(d) Bypassing intended solution path**: Intended path is Go implementation with `ShardingProxy` struct, weighted (Turn2) and simple mod (Turn1 eased) with MD5 big-endian, broadcast `global:` (set to all, get checks all in id order, delete from all, `get-shard-id -1`, `get-shard-path` comma-separated), checksum without HTML escaping (`SetEscapeHTML(false)`), atomic writes, corruption backup with missing-checksum-as-corruption (including data field with missing checksum), fallback to legacy, migration with duplicate/wrong-shard cleanup (only correct weighted shard retains non-global, global replicated to all), ops.log replay file order (tombstone delete prevents resurrection), help explicit for bare no-args and `migrate --help` (including `version, shard_id, checksum` for Turn2 hard, but not required for Turn1 eased). Anti-bypass: stdlib-only via `go.mod` require lines **and** `go list` imports (no dot), atomic write via `CreateTemp`+`Rename` + `SetEscapeHTML` source inspection, batched migration via `grouped`/`map[int]` and single `atomicWrite` per shard loop, checksum verified via file containing `data`+`checksum` with valid `md5(sorted_json_no_spaces_no_escape)` and raw `<` present, duplicate cleanup seeds same non-global key in all shards and asserts only correct weighted shard retains after migration, ops.log replay sets key via proxy (log), creates legacy with same key different value, resets shards empty keeping log, migrates, asserts log's newer value wins, config validation expects exit 2 **and no stdout** (`stdout==""`) – printing to stdout fails, help bare and `migrate --help` must exit 0 containing specific words, corruption init must repair **every** shard (corrupts all 4, `list-keys` should create 4 `.corrupt.` backups) – on-read-only repair would leave some corrupted, missing checksum field with `data` field must be treated as corruption (backup), as per feedback.

Both milestones fail before solution (skeleton `main.go` prints not implemented exit 1) and pass after reference solutions (Turn1 43/43, Turn2 43/43 after empty-string fix, harness reward 1, structural 9/9 PASS, `is_memorizable=false` after removing exact Go hashing snippet, total_score 16/18, Oracle 3/3), with no solution files in runtime image (Dockerfile only creates skeleton `main.go`, not copying `solution/`).
