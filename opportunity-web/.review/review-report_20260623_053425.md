## 9. Revised Instruction

Spec Clarity is "Requires Some Guessing", so revisions are warranted. **Per AAI policy, a 3P agent must not author `instruction.md` content** — so rather than paste a rewrite, here are the targeted, mechanical edits for the participant (or Avocado) to apply:

*Succinct change list:*
1. Fix typos: "inlcude"→"include" (#6), "mathces"→"matches" (#3), "confidnece"→"confidence" (#5), "the provide reps data"→"the provided reps data" (#7), "opportunites"→"opportunities" (throughout).
2. Make the performance requirement explicit (Note #3): state that the table must **not render all rows into the DOM at once** — show at most a bounded page/window (e.g. paginate ~50 per page; virtualization is also acceptable) — so "efficiently" is unambiguous.
3. Disambiguate the summary (#2): the header count/total reflect **all opportunities matching the current filters/search (the full result set), not just the rows on the visible page**.
4. (Optional, for fairness) Make the two ~implied behaviors explicit: (a) per-opportunity status/assignee stay tied to the opportunity across re-sorts; (b) when a row's status changes so it no longer matches an active status filter, it leaves the table immediately.

No changes needed to the tests, oracle, or environment — they are sound; these edits only close the spec↔test wording gaps. Difficulty is preserved (the bounded-window requirement remains; we are only making it fair, not easier — empirically Opus/Avocado already pass it ~4/5).
